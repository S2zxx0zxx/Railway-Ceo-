# Owner execution protocol — 2026-11-26
Authority: owner's latest instruction to implement one task at a time, retain all evidence, defer blocked tests/CLI/CI, continue with the next eligible task on one-click START, and retry all outstanding verification at the end. This supplements V5 section 7; it does not remove licensing, actual functional dependencies, scope or final acceptance requirements.

## Implementation-first pass
- Reopen exact master plan, V5 traceability registers, V4 private evidence and current PR #2 HEAD/STATE at every START. Treat missing source as a blocker, not permission to guess. Preserve immutable originals and PR #1/main.
- Execute only the authorized R task in full. Finish all implementable subwork, author the required tests and run available checks, fix readily reproducible issues. No premature advance just because implementation is difficult.
- Do not wait indefinitely for pending CI, inaccessible CLI, device, environment or external evidence. If implementation is complete but checks cannot finish, use IMPLEMENTED_UNVERIFIED; if implementation itself cannot be completed, use BLOCKED with exact missing dependency and remaining work. Never call either PASS.
- Record each unfinished verification in DEFERRED_VERIFICATION.csv with task, exact commit, command/run ID, last observed result, reason, dependency impact and retry action. Retain GP/E/UI/resource mapping and actual evidence; update STATE and EXECUTION_LEDGER at every checkpoint. For new tasks keep per-task report with code paths, acceptance, tests/exits, artifacts and hashes. Pending/failing checks remain visible; no suppression or fabricated pass.
- Move to next lowest eligible ID on owner's one-click command. An implemented-but-unverified predecessor may be used provisionally for isolated compatible development if its code/interface is available and no known correctness, rights or safety defect prevents it. Record provisional dependency links; descendants cannot gain final acceptance before prerequisites are verified. Missing required implementation, data, rights or hard contracts must block dependent work; continue genuinely independent work. No false N/A or changes to immutable DAG.
- Offer one concrete next command at every checkpoint. No automatic start of another task without the owner's next click, and no background work claims.

## Final reconciliation pass
- After implementation pass through R01–R54 (or all reachable work), retry every deferred and failed check, rebuild dependency order, repair failures and re-run affected descendants and full regression on exact final source. Resume blocked implementation as soon as prerequisite available. Keep reproducible command, exit, CI URL, tested revision and artifact evidence for each.
- Close deferred rows only on actual evidence; maintain separate implementation count, accepted count and blocked count. No final G0–G6 PASS with required blockers, no production release or merge until actual acceptance, signed/device evidence where required and explicit owner approval. Existing legacy CI is not railway gameplay proof.
