# G08 save and simulation contract

- Domain uses integer game minutes and the existing seeded PRNG. Wall time is read in the persistence adapter, never inside domain events. The cap is 1,440 elapsed real minutes before speed multiplication (up to 86,400 game minutes at 60x). Backward clock jumps do not simulate negative time; preserve the saved baseline. Paused/terminal games advance no simulated time.
- Scheduler order at a timestamp: expiry, daily obligations/market/rescue, due jobs sorted by ID, scheduled plans, crisis deadline review, operating guard, manager decisions, milestones. This is current engine order, not a claim that all MASTER_BUILD_SPEC priority cases are accepted. Timing and same-timestamp edge cases require regression tests.
- Worker receives immutable snapshot and wall time; produces candidate state and report, never touches IndexedDB. Chunks default to 360 game minutes, revision increment once for elapsed proposal, not once per chunk. Unsupported Worker constructor falls back to cooperative UI yields. Worker errors/timeouts reject without writing; work restarts from saved state on retry, not a persisted partial checkpoint.
- Compare snapshot version, integrity and company identity inside short Dexie write transaction. Commands still use receipt history (512) and revision check. A stale proposal cannot publish over another tab. Legacy records are validated before new integrity metadata is generated. Whole transaction includes rotating backups and active record; archived companies use distinct keys. No automatic destructive recovery.
- Portable format: the-ceo-save envelope v1, content v1, build 0.1.0, payload JSON string and CRC32 of UTF-8 payload. Stored checksum also covers version and command receipts. CRC32 detects accidental corruption; does not authenticate or prevent deliberate editing. Raw schema-1 JSON import remains supported; unknown versions rejected. Payload limit 8 million characters; envelope limit 17 million characters. Very large games may hit schema limits; retention/storage sizing needs later verification.
- Backups: backup, backup:1, backup:2. Rotate on meaningful domain changes/commands, not wall-only ticks. Recovery tries newest valid then older; explicit import/recovery pauses. Archives remain local; export before clearing browser/app data. Web and Android share file format, not storage.
- Return brief is computed from before/after state, displayed after significant elapsed intervals or clock anomaly; session-only. No background execution promised.
- Pending: actual unit/browser/Android execution, chunk parity across all event classes, crash injection/low quota, native lifecycle and share/file picker, measured UI stall and long-run performance, service-worker asset and safe-update evidence, persisted report/checkpoint if required. No gate pass.
